The finding that cost the most, and is worth the most

Every Direct Lake model this engine had built used the Direct Lake on OneLake connector AzureStorage.DataLake(…). Against a Fabric Warehouse that form validates on create, loads its metadata, and draws all twelve tables with their relationships and measures in the modelling canvas — and never binds a single table. Every visual returns Missing_References.

The one-line fix

Sql.Database("<workspace>.datawarehouse.fabric.microsoft.com", "<warehouse item id>")

Swapping the connector was the whole of it. The model then matched Warehouse truth on 14 of 14 measures, the zero-relationship probe passed, and all seven visual types rendered clean across all four warehouse schemas.

The engine did not carry a guess forward. It carried a shape that had been correct twice, in two delivered projects, and every repetition made it look more settled. P27 is the first time this engine pointed Direct Lake at a Warehouse.

The rule this leaves behind. Grep a delivered sibling, never write a shape from memory — and record what the sibling was proven against. A shape's proof is scoped to its source; repeated success against the same source type is not evidence for a different one. Choose the Direct Lake connector from what the SOURCE is, and prove it with a two-table probe before building on it.

Why nothing mechanical caught it

The OneLake form is a legal datasource kind. The create validator accepts it, get_item_definition reads it back intact, validate_pbip.py and the PBIR schema validator both pass, and the modelling canvas draws the whole model. Only a rendered value, checked against a number computed somewhere else, can see it — which is §132 in its sharpest form.

The split-session number — and the correction this page had to make

cr/turn is the quantity the split-session hypothesis predicts stays flat rather than growing. P27 reads 432,257 → 398,987 → 458,855. It is not flat, and Session 3 is the highest of the three.

This panel originally said the opposite. The mid-session checkpoint at 06:25:29Z read 398,183 — a tidy flat-to-falling result. The mandated close re-capture at 06:40:37Z, taken after the handover as §113/§125 requires, read 458,855. Fifteen minutes of writing moved it 15%.

The finding underneath is worth more than the number: the close ritual is the most expensive part of a session per turn — maximum context depth, output-heavy — so any session that snapshots before its close reports a flattering figure. P27 cannot settle the hypothesis either way, because its three sessions did different work: S1 built, S2 diagnosed, S3 verified and closed.

Why a clean render proved nothing

Power BI silently drops a general.altText binding to a missing measure. The republished report shows 28 containers, 0 error visuals, every figure matching Warehouse truth — pixel-identical to a correct build with all 32 bindings broken. ALTTEXT_COVERAGE 32/32 passing on disk says nothing about the tenant.

So the alt measures were bound as visible values on an AltProof card in the check report, which fails loudly and names them: Something's wrong with one or more fields: (MTM Daily) MTM alt text, (MTM Daily) Open Positions alt text, (Exposure Daily) Breach count alt text. That card is left in place and left failing on purpose — it is the live regression test. When it renders three sentences instead of an error, the item is closed.

This is the project's central lesson arriving a second time: a clean-looking render of a broken model is indistinguishable from a correct one unless the number came from somewhere else. First it was the Direct Lake connector; now it is a formatting property. Same trap, different surface.

Both automated routes were then measured, and both are closed

Core MCP. Rebuilding the model from source and computing both payloads deterministically: 60,490 without the alt measures (this is what is live) versus 69,186 with them. The alt measures cost 8,696 payload chars and the gap to the known-good is 8,696 — there is no slack. Every reclamation was measured: dropping inert SummarizationSetBy annotations saves 944, blank-line padding 616, and column sourceLineageTag 4,308 — but that last one is the protected Direct Lake diagnostic the contract forbids reverting. All three together still land at 63,330, above the wall. No safe compaction exists.

XMLA/TOM. Taken as the next channel down per contract §4. The channel is real — ListConnections returned a live connection object to SM_PalmDesk over the workspace XMLA endpoint, minted outside the session on 2026-09-06. Its token had expired, and every ConnectFabric re-auth returned Device did not respond within 60s: the interactive sign-in cannot finish inside the device bridge's 60-second call ceiling. XMLA is usable from a session only while a token minted outside that session is still valid — after which it carries batch model edits of unbounded size, because the payload never has to be one agent utterance. It is the only known way past the emit ceiling, and one sign-in on the machine before a session unlocks it.
